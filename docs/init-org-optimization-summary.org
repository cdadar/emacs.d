** use-package 结构收敛
- 将多个分散的 ~(use-package org ...)~ 收敛为单一主块。

  - ~:custom~ 放基础变量
  - ~:hook~ 放简单 hook
  - ~:bind~ 放按键绑定
  - ~:config~ 放函数定义与集中初始化调用

** Hook 与 keymap 整理
- 将反复在 hook 中修改 ~org-mode-map~ 的逻辑移出，避免每次进 buffer 重复做全局 keymap 修改。
- 将截图命令抽成独立函数，并绑定到 ~C-c s c~。

- 在 ~org-mode~ 中启用窗口内软换行，长 heading 与长行内容会在窗口内自动换行显示。

  （18 个码点，U+05B0-05EA）落在 ~texgyretermes-regular.otf~ 上：正文里的希伯来文/

- 回退：~cdadar/org-latex-glyph-fallback-ranges~ 加希伯来文区间（U+0590-05FF，
  字母 + 元音符号 niqqud + 读经记号）→ 新家族 ~\cdadarheb~
  （~\IfFontExistsTF{SBL Hebrew}~ 否则 DejaVu Sans，带 ~Script=Hebrew~：niqqud 的
  mark 定位靠这个 script tag）。映射仍只对导出文本里真出现的字符注入。
- 手动命令 ~cdadar/org-wrap-hebrew-greek~（=M-x=）：把正文里裸着的希伯来文/希腊文
  包成笔记前言的 ~\heb{}~ / ~\gr{}~（= ~\texthebrew~ / ~\textgreek~）。一段 =

  整体算一次 undo，返回包的个数。
- 只在笔记前言定义了该文种简写（={\heb}= / ={\gr}= 字面串）时才包；没定义就跳过该文种

  sequence=，于是改成只认简写、宁可跳过也不猜宏名（那 3 篇的裸字符由回退映射照常渲染）。
- 两个实测的 elisp 坑：~looking-back~ 会写 match data ——（1）helper 内要

  ~\hebl{}~ 等变体/混合行/幂等/无宏跳过/只声明 polyglossia 也跳过/只有希腊文定义时

** 标记类：新标记用内置命令，失效的旧标记用 cdadar/org-fix-emphasis-boundaries
- 需求是「给选区套 ~*~、~+~、~-~ 这些标记」，org 自带三件，不必写命令：
  - ~C-c e~ → ~org-emphasize~：敲一个字符（=*= 粗体、=/= 斜体、=_= 下划线、~=~ 等宽、
    =~= 代码、=+= 删除线）包住选区；没有选区时作用于光标处的词。
  - ~C-c -~ → ~org-ctrl-c-minus~：把选中各行变成列表项，再按一次切换项目符号 / 变回
    普通文字。
  - ~C-c *~ → ~org-ctrl-c-star~：把选中行变成标题。
- 只有 ~org-emphasize~ 需要补绑定：上游默认**没有**给它设键（只有菜单项
  =Emphasis...=），而习惯上写的 ~C-c C-x C-e~ 在本配置里是 clock 的
  ~org-clock-modify-effort-estimate~，所以本配置把它绑到 ~C-c e~（=init-org.el= 的
  org ~:bind~ 块）。~C-c -~ 与 ~C-c *~ 本来就是 org 的默认绑定。
- 上面说的是**新写**标记；已经写好、但标记紧贴汉字而失效的存量（=说*重点*好啊=、
  =2. *结论*：…=）内置命令补不了（~org-emphasize~ 只补它自己新插入的标记），所以另加
  =cdadar/org-fix-emphasis-boundaries= （ ~C-c C-x F~ ，上游没占这个键）：
  - 判定照解析器来：开标记前只能是空白、~-~、ASCII 括号引号 ~{~ 或行首，闭标记后只能是
    空白、~-~、ASCII 句读括号或行尾（=cdadar/org-emphasis-opening-chars= /
    =cdadar/org-emphasis-closing-chars=，注释里标了出处；不是
    ~org-emphasis-regexp-components~）。
  - 只有**失效的那一侧**紧贴非 ASCII（汉字 / 全角标点 / 破折号）才算强调：=a*b*c= 、
    sdk=[34,35] … sdk=34 这类全 ASCII 的算式与标识符不动， =**重点**= （org 自己就认）
    与标记连写也不动。曾按「内容里有中文也算」放宽过一档，实测会把 sdk=[34,35] … sdk=34
    这种 = 运算符成对命中（补完前后各多一个空格），已去掉；代价是两侧全 ASCII、只有内容
    带中文的那种不动，要它让 ~C-c e~ 补。
  - 处理哪几个标记由 =cdadar/org-emphasis-markers= 定，默认就是「粗体 / 下划线 / 等宽 /
    代码」四个：
    - =/= 排除：中文里几乎都是路径与并列分隔符（=图像/视频= 、 =视频_素材/杂项= ）。
    - =+= 也排除，是**实测**结论：近 120 天笔记里 =+= 成对且紧贴汉字的只有 4 处，
      全是加号 / 连接符（.rtf 14.9万+.doc 11.8万 、（杂项+待定+按格式_PDF）），
      补空格会把它们真变成删除线；同一批语料里 =*= 命中 261 行、~=~ 312 行、=~= 5 行、
      =_= 0 行，命中的全是该修的强调。要 =+= 就把它加回那个字符串。
  - 只在 org 会解析强调的节点里动（=paragraph= / =headline= / =table-cell= /
    =quote-block= / =verse-block= 等）：src / example / export 块、链接（含中文文件路径）、
    =verbatim= / =code=、LaTeX 片段、=#+NAME:= 这类关键字一律不动 —— 那里标记不是强调，
    补空格是破坏引用/路径。
  - 无选区跑整篇、有选区只跑选区；整篇算一次 =undo=，可反复跑（修好的不再是候选）。
  - 补的空格落在标记外侧，所以 =*结论* ：= 这种「全角标点前多一个空格」是必然产物；
    想排版干净就别让标记紧贴全角标点（写完立刻 ~C-c e~ 一下即可）。
  - 实测（加载真实配置后 batch 跑）：10 条失效样例全部补好且 ~org-element-context~
    认成 =bold= / =code= ；15 条不该动的（算式、= 运算符、加号连接符、=图像/视频= 、
    src/example 块、链接路径、=#+NAME:= 、=verbatim= 、=#+TITLE:= 、本来就对的、=**重点**= ）
    一律未动；行尾不补空格、第二次跑 0 处、region 只跑选区、非 org buffer 报错、
    中途报错整个回退；导出链路上 LaTeX 里真的出现 =\textbf{重点}=。真笔记
    =20261010111541-vidhub_vs_infuse_player_core.org= 跑一遍 bold 对象 7 → 19（补 12 对），
    diff 逐行看过只多了边界空格。
- 实测结论（解释为什么内置就够，也解释中文笔记里为什么强调两边都带空格）：
  - ~org-emphasize~ 自己会补边界空格：~说重点好啊~ 选中 ~重点~ 按 ~C-c e~ =*= 得到
    ~说 *重点* 好啊~；~foo bar~ 选 ~bar~ 则不加多余空格。
  - org 9.8 的解析器把强调边界**写死**在 ~org-element--parse-generic-emphasis~ 里
    （开标记前只能是空格、~-~、ASCII 括号、引号、~{~ 或行首；闭标记后只能是空格、
    ~-~、句读、ASCII 括号或行尾）。~org-emphasis-regexp-components~ 只影响 org.el 的
    font-lock：改它以后 Emacs 里看着像粗体，解析与导出却仍不认（实测），所以没动它。
    这也是笔记里强调一律带空格的原因（=是 *「不明白」* 。=）。
- 验证：~where-is~ / ~key-binding~ 查出三个键分别是 ~org-emphasize~、
  ~org-ctrl-c-minus~、~org-ctrl-c-star~；内置命令实测输出 ~说 *重点* 好啊~（补空格）、
  ~foo *bar*~（不补）、~- 文字~ 与 ~- a~ + ~- b~（列表项；再跑一次变回普通文字）。

** newunicodechar 重复定义同一字符会死循环
- 现象：~摩西五经概论~ 导出报 =! TeX capacity exceeded, input stack size=10000=，
  卡在 ~\item ▸~。
- 原因：~\newunicodechar~ 把字符设成 active；如果该字符已经 active（笔记 header 已映射），
  再定义一次时，**替换文本里那个字符会被当成 active token 再展开**，于是无限递归。
- 修法：~cdadar/org-latex-glyph-fallback-chars~ 遇到文本里已有
  ~\newunicodechar{<该字符>}~ 的字符就跳过（~cdadar/org-latex-unicodechar-mapped-p~）。
- 验证：该笔记重新导出，0 错误 0 递归，PDF 正常。

** 没声明字体的笔记给默认 CJK 字体
- 现象：一篇不写 ~#+LATEX_HEADER~ 字体的中文笔记，导出后每个汉字都是空白
  （实测 46 个 =Missing character=，全落在 lmroman 上）。
- 新增 filter ~cdadar/org-latex-default-cjk-font~：文档里没有
  ~\setCJK\(main\|sans\|mono\)font~ 且确实含中日韩字符时，在
  ~\begin{document}~ 前插 ~\usepackage{xeCJK}~ + 本配置的 ~cdadar/org-latex-cjk-main-font~
  （main/sans/mono 三个）。
- 不动的情形：已声明 CJK 字体、文档里没有 CJK 字符（纯英文不加 xeCJK）、
  没有 fontspec（pdflatex 文档不能塞 xeCJK）、已注入过。
- 验证：裸中文笔记导出 0 缺字，渲染出的汉字正常；~教會生活~ 没被重复注入；
  「polyglossia 但无 CJK 字体」 的合成笔记也 0 错 0 缺字。
- 只补 CJK；英文主字体仍是 LaTeX 默认的 Latin Modern（要统一成 TeX Gyre Termes 另说）。

** 两处笔记自身的毛病
- ~20250219220537-医治枯手的耶稣_ppt.org~：~\setCJKmainfont~ 写在
  ~\usepackage{...xeCJK}~ 之前（xeCJK 还没加载），把 usepackage 行上提一行。
- ~20260912230726-教會生活.org~：删掉一个孤立的 PUA 字符 U+F076（网页图标残留，无字体可渲染）。

* 本轮：quote 字号写在笔记前言（2026-10-10）

** 字号由前言里的 ~\cdadarquotefont~ 决定
- 字号不放进 ~lisp/init-org.el~ 的导出 filter：filter 会连带影响所有笔记与文章类
  导出，而字号是每份 deck 自己的排版选择，和字体、边距一样属于前言。
- 前言 / ~snippets/org-mode/export_beamer~ 的 quote 环境里加：
  ~\newcommand{\cdadarquotefont}{\ifdim\f@size pt>14pt \fontsize{14}{14}\selectfont \fi}~，
  由 ~\renewenvironment{quote}~ 的 begin 段在 ~\list~ 之前调用。
- 只在正文比它大时生效：17pt 的 deck quote 是 14pt；正文本身 ≤14pt 时（拥挤页在正文里
  手写 ~\fontsize{10}{10}\selectfont~）quote 跟随正文，不会被反过来放大。
- 调用点在 ~\begin{quote}~ 的组里，字号不泄漏到该页其余内容；放在 ~\list~ 之前与
  「正文里手写字号」的效果一致（放进 minipage 会让 quote 外围按 17pt 行距留白，
  整页内容变高、位置漂移：实测第 2 页段落起点差约 4-8pt）。
- 单篇换字号：改前言里的 14pt，或 ~\renewcommand{\cdadarquotefont}{...}~。

** 验证
- ~20261010224029-感恩的生活_ppt~（17pt deck，9 页）逐页渲染比对：
  - 与改动前比：只有第 2 页变（frame A 诗50:23 的 quote 由 17pt → 14pt，全文唯一
    没手写字号的 quote）；手写 ~\fontsize{10}{10}\selectfont~ 的那页
    （frame B a) 旧造的本性，6 处引用）逐像素一致。
  - 与「按 init-org.el filter 注入」的临时版本比：9 页 300dpi 逐像素一致，
    证明前言写法与 filter 等价。
- 字号写在 ~init-org.el~ 的临时版本已回退；文章类导出（如
  ~20241120194527-耶稣的救恩_召罪人~）不受影响。

还可以按同样思路继续整理：
- ~org-ref~
- ~org-journal~
- ~org-zettel-ref-mode~
- ~org-roam-bibtex~

目标是让这些块都更接近统一风格：
- 简单配置用 ~:custom~

- 复杂逻辑用 ~cdadar/...-setup~

** 将部分大型数据结构拆到常量或专用函数
以下内容仍然偏大：
- ~org-agenda-custom-commands~
- ~org-capture-templates~
- ~org-roam-capture-templates~

- 或抽成返回值函数
- 或按主题拆分（如 work / notes / anki / protocol）

这样对 diff 和后续维护会更友好。

** 进一步统一新旧命名空间
目前遵循了“新改的替换，原本的不用替换”的要求。
未来如果想彻底统一风格，可以考虑逐步把旧的 ~sanityinc/~ 名称迁移到 ~cdadar/~。
但这应作为单独、可控的改动来做，而不是顺手混改。

* 暂不建议动

** 不建议一次性全量改名旧 ~sanityinc/~ 标识
原因：
- 已有名字分布较广
- 可能影响用户习惯、历史配置和 muscle memory
- 本轮已经明确约束为“只改新整理出来的部分”

如果要做，应单独作为“命名空间迁移”任务处理。

** 不建议把所有逻辑都强行塞进 ~:custom~ / ~:hook~
有些逻辑天然更适合保留在函数和 ~:config~ 里，例如：
- advice
- 复杂 capture 模板生成
- Babel 图表工具发现
- Agenda 跳过逻辑
- 自定义命令定义

过度声明式化会让结构更隐晦，不一定更好维护。

** 不建议恢复运行时自动安装 diagram 依赖
已经移除的做法不建议再加回来：
- 启动时联网下载 jar
- 配置加载时执行 unzip / shell 安装流程
- 用不安全的远程源自动取文件

更稳妥的方式应是：
- 明确安装
- 明确路径
- 明确环境变量

** 不建议短期继续大规模重排整个文件顺序
当前已经完成了几轮结构重构并通过验证。
继续大幅重排会增加：
- diff 噪音
- 回归排查成本
- 未来 blame 难度

如果后续还要重排，建议基于明确目标单独进行，例如：
- “只整理 capture 区块”
- “只整理 roam 区块”
- “只整理 export/babel 区块”
